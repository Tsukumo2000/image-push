## 一句话结论

**别指望"插件自带漂亮界面"——三个候选解包看了，`lib/` 里只有 `plugin/` 和 `core/`，一个 `client.js` 都没有。**

真正能出图的是 DSH 自带的 Office 技能：`office-pptx` 用 python-pptx 造**原生图表**，
而 DSH 随包的 Python（3.12.14）里已经装好了 python-pptx / openpyxl / pandas / PIL——**不用 pip、不用联网**。

今早已经用它生成了 `demo_store_replenish.pptx`，验证含 `ppt/charts/chart1.xml`，是真图表不是图片。

## 推荐：候选一 dsh-store-replenish（零售补货）

| 项 | 核实结果 |
|---|---|
| 版本 | 0.2.2 |
| 作者/仓库 | PerryLink / github.com/PerryLink/dsh-store-replenish（3 star，11-22 更新） |
| License | Apache-2.0（可商用、可内部传播） |
| 依赖 | **零运行时依赖** |
| 体积 | 0.95 MB |
| 要求 | engines.dsh >= 0.2.1-rc.3，node >= 24.9 |
| 我跑到哪 | **A 级**：解包 + 补 peer + 用随包 Node 跑 quickstart，真出输出 |

quickstart 实际输出（原文）：
```
30-day window: 16 store-SKU rows, 11 order line(s), 398 unit(s), 4,768.80;
2 stockout risk(s), 1 slow-moving
上海静安店: 6 order line(s), 282 unit(s), 2,908.20, 2 risk (medium)
成都高新店: 5 order line(s), 116 unit(s), 1,860.60, 0 risk (low)
```

为什么选它：
- 唯一同时满足「零依赖 + 纯本地 + 数据是扁平 CSV + 结论天然适合画图」
- 补货建议本身就是「门店 × SKU × 缺口」表格，画柱状图不需要任何编造
- 业务话术好懂：**少压货、不断货**

演示脚本一句话：**「把这张门店库存表变成补货单，并做成这页图。」**

## 必须知道的风险（今早报告纠正了我昨晚的说法）

**1. 我昨晚说"dsh-genui 已装上" —— 说得不严谨，已核实纠正**

实际情况：genui 装在 **headless profile**，`profiles/desktop/node_modules/` 里**没有**。
所以桌面版界面里现在看不到 genui，别去界面里找。

**2. genui 有真实离线风险，之前没发现**

`dsh-genui@0.3.4` 的 runtime 里 grep 到 **2 处 `registry.npmmirror.com` 引用**
（TinyVue / Element Plus 组件库 URL，在可视化 schema 设计器配置里）。

无法确认正常图表路径会不会加载它们——**如果会，内网就白屏**。
要上 genui，必须先断网实测一次。这条比"好看不好看"重要得多。

**3. 三个候选都没有自己的前端面板**

「可视化多」在这几个包身上是假的。真要靠 DSH 内置 office-pptx 出带原生图表的 PPT。

## 内网最短路径（若采纳候选一）

1. 先确认内网 DSH 版本 ≥ `0.2.1-rc.3`（本机是 rc.2，差一个版本）
2. 打包 `dsh-store-replenish@0.2.2` tarball + 一份样例 CSV（10 列：门店/SKU/销量/库存/在途/安全天数/周期/起订量/单价）
3. 照抄 `financial-analyst-offline` 的 preset 骨架，persona 改成「补货分析师」
4. 挂 `dsh-skill-office` + `dsh-tool-workspace-dependencies`，用随包 Python 调 office-pptx 出图
5. 兜底：pptx 不顺就用 `office-xlsx` 出表格 + `present` 交付，不依赖 LibreOffice

## 我核实不了的（诚实清单，明天别当已知事实用）

1. **内网 DSH 实际版本** —— 三个插件都要 >= 0.2.1-rc.3，本机是 rc.2。
   我是在「补 peer 直接调 tool.execute()」这层跑通的，**没走 DSH 插件加载器和引擎校验**。
   所以"算得对"验证了，"装得上"没验证。
2. **内网能否连 npm / 能否带 node_modules 进去** —— 这台机器无法判断
3. **截图没做目视核验** —— 浏览器工具因缺系统 node 启动失败。
   "界面好不好看"是二手描述，演示前请亲眼看 `docs/assets/quickstart.png`
4. **genui 在 0.2.1 正式版能不能渲染** —— 见上面风险 2，那条 npmmirror 引用必须断网验证
5. **dsh-excel-reconcile@0.1.7** 只核了元数据（B 级），没跑过
6. **插件目录可信度** —— 用的是 `dsh-plugin-catalog`（宣称 13,281 条），
   我只对我实际解包的 6 个做了交叉验证，结果一致
7. **`dsh plugin --profile add` 语法** —— 从 README 抄的，本机没实际执行过
